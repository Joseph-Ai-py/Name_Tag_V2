# 5-A. Authentication / Authorization

로그인을 추가하면서 Backend에 **Identity Layer**를 도입한다.

```text
Request
 ↓
Authentication
 ↓
Current User
 ↓
Authorization
 ↓
Brand Membership / Role
 ↓
Resource
```

## V1 인증 방식

V1은 다음을 기본으로 한다.

```text
Email + Password
        ↓
FastAPI Auth Service
        ↓
Secure Session Cookie
```

비밀번호는 평문으로 저장하지 않고 Argon2id 계열의 password hashing을 사용한다. 세션 식별자는 브라우저 `localStorage`에 저장하지 않고 보안 쿠키를 사용한다.

쿠키 정책은 배포 구조에 맞춰 `HttpOnly`, `Secure`, 적절한 `SameSite`를 적용하며 cross-site 요청을 허용하는 경우 CSRF 방어를 함께 적용한다.

### 인증 API

```text
POST /api/auth/register
POST /api/auth/login
POST /api/auth/logout
GET  /api/auth/me
POST /api/auth/forgot-password
POST /api/auth/reset-password
```

이후 Google/OAuth 등의 외부 인증 제공자는 동일한 User 계정에 연결되는 Identity Provider로 확장할 수 있다.

## 인증과 권한을 분리한다

Authentication:
> "누구인가?"

Authorization:
> "이 Brand의 무엇을 할 수 있는가?"

따라서 단순히 로그인했다고 모든 Brand 데이터에 접근할 수 있게 하지 않는다.

### Brand Role

```text
owner
editor
viewer
```

`BrandMember` 테이블을 통해 권한을 확인한다.

# 7. Agent의 핵심 기술

## Orchestrator

Agent 전체 실행을 담당한다.

```python
async def run_agent(request):
    context = await context_manager.build(request)
    route = await router.route(request.message, context)
    result = await skill_registry.execute(route, context)
    return result
```

## Router

사용자 요청을 적절한 Skill/Research mode로 분류한다.

예:

```text
"경쟁사를 조사해줘"
→ Research

"타겟을 바꿔줘"
→ Customer

"브랜드가 너무 딱딱해"
→ Brand / Visual

"로고 다시 만들어줘"
→ Visual / Asset
```

## Tool Registry

Agent가 호출할 수 있는 실제 행동을 등록한다.

예:

```text
get_brand_context
propose_brand_change
search_web
create_research_job
generate_text
generate_image
update_document
save_asset
```

# 14. Server Persistence

브라우저 localStorage는 장기적인 BrandState 저장소가 아니다.

기존 localStorage 기반 상태:

```text

appliedSelections
기타 legacy state
```

은 migration adapter를 통해 서버 상태로 이전하는 것을 원칙으로 한다.

```text

 ↓
Migration Adapter
 ↓
Server API
 ↓
Brand / Conversation / History
```

사용자 데이터가 있는 상태에서 기존 localStorage를 단순 삭제하지 않는다.

# 19. Quick Research / Deep Research

## Quick Research

* 단일/짧은 질문
* 1~5개 정도의 출처
* 빠른 답변
* 낮은 latency

## Deep Research

* 여러 질문을 동시에 해결
* 다중 출처 비교
* 시장/경쟁사/고객 분석
* 장문 보고서
* 전략적 의사결정 지원

Deep Research는 NAME TAG 전체 개발의 첫 단계가 아니라 **Research Engine의 고급 실행 모드**다.

# 32. NAME TAG의 기술 철학

NAME TAG는 기술을 많이 사용하는 서비스가 아니라 **필요한 기술을 필요한 시점에 사용하는 서비스**를 목표로 한다.

```text
Product Need
 ↓
Simple Architecture
 ↓
Working Feature
 ↓
Measure
 ↓
Only then Scale
```

핵심은 최신 기술의 집합이 아니라 다음 구조의 안정성이다.

```text
Persistent State
+
Agent
+
Skills
+
Tools
+
Research
+
Workspace
```
